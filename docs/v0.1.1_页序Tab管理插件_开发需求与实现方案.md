## 1. 背景、定位和目标

当浏览器开启大量 Tab，顶部横向标签栏无法完整显示每个 Tab 标题，切换及排序成本较高。

**页序**定位为轻量级浏览器 Tab 管理扩展：用快捷键唤出不占用网页布局空间的独立可拖动浮窗，以竖排方式展示完整标题；既能快速切换，也能手动或自动整理，并且排序结果**必须反映在浏览器实际 Tab 的先后顺序中**。

### 1.1 v0.1.1 必须交付的功能

1. 独立竖排 Tab 管理浮窗；标题完整可查看；点击目标 Tab 切换页面。
2. 可配置快捷键和插件图标唤出；同一时间不重复创建多个管理窗口。
3. 点击 Tab 后可设置关闭管理窗或继续保持窗口存在，设置持久化。
4. 在浮窗中拖动 Tab 行手动排序，实时改变浏览器 Tab 的实际顺序。
5. 浏览器顶部顺序从左到右 = 管理窗口列表从上到下；双方变化实时同步。
6. 一次性自动排序：按网页标题、网站域名、完整网址，可选升序和降序。
7. 浮窗自由移动/手动缩放，关闭再开启记忆位置及尺寸，支持多屏环境。
8. 仅通过一个“自动适配窗口大小”按钮，根据当前 Tab 标题和数量**按需**调整浮窗宽高。
9. 辅助体验：当前 Tab 高亮、favicon、搜索框、Tab 数量、操作错误反馈。

### 1.2 本版不做

- 浏览器侧边栏（Side Panel）模式；本版明确选择独立浮窗（方案 C）。
- Windows 系统级“始终置顶”（不引入本地常驻程序或 Native Messaging）。
- Tab 内容/正文读取、书签/历史记录管理、会话备份、云同步。
- 跨浏览器/跨窗口批量移动 Tab，自动创建或拆分 Tab Group。
- 持续、定时或后台自动重排 Tab；自动排序仅在点击执行按钮后发生一次。
- Firefox 兼容性及插件商店正式上架。

## 2. 窗口形态与操作流程

### 2.1 独立窗口

- 使用 Chromium 扩展 API 建立 `type: popup` 的**浏览器独立窗口**，加载扩展内部的管理页面。
- 与普通工具栏 action popup 不同，该窗口可使用原生窗口标题栏拖动、缩放、最小化和关闭；不显示浏览器普通地址栏及标签栏。
- 不需要改动网页本身的布局，浮窗可与主窗口重叠，亦可移至第二显示器。
- 页面默认仅管理**唤出时对应的正常浏览器窗口**，浮窗本身不加入被管理 Tab 列表。
- 再次快捷键唤出，若浮窗已存在则将同一窗口聚焦至前台；不创建第二个。
- 点击标签切换到浏览器主窗口时，浮窗可能被主窗口遮挡。**“保持”仅代表未关闭，非系统级置顶**。
- 关闭浮窗时不关闭、不修改普通浏览器 Tab。

### 2.2 界面建议

```text
┌────────────────── 页序 ──────────────────────┐
│ 搜索标题或网址…                    [自动适配] │
│ 当前窗口：28 个标签                [排序选项] │
├──────────────────────────────────────────────┤
│ ⋮⋮  🌐  ChatGPT - 软件开发排查与分析          │
│ ⋮⋮  🌐  GitHub - Yexu                        │
│ ⋮⋮  🌐  Schaum's Outline of Mathematical…   │
│     （窄窗口下可换行 / 悬浮查看完整标题）     │
│ ⋮⋮  🌐  其他 Tab ...                        │
│                    （超过可见范围时滚动）     │
├──────────────────────────────────────────────┤
│ [ ] 点击 Tab 后保持窗口打开                  │
│ 排序方式：[手动 / 标题 / 域名 / 完整网址 ▼]   │
│                                [执行排序]    │
└──────────────────────────────────────────────┘
```

- 行内容建议：拖动手柄、favicon、标题、可选小字号域名、活动 Tab 标记。
- 完整标题必须可获取：窄窗口允许换行；如为控制行高而省略显示，必须提供悬浮提示或点击展开全文，不能永久截断。
- 正常列表示浏览器真实 index 升序，不因同域名/标题而视觉分组重排。
- 标题为空以 URL 或“未命名标签页”代替；图标缺失采用默认图标；浏览器内部页面也不崩溃。
- 搜索支持标题和 URL，不区分大小写，过滤后保留真实相对顺序；搜索本身不调整真实 Tab。
- **搜索结果过滤期间暂停拖动排序和自动排序**，避免隐藏项造成排序歧义；清空搜索恢复全列表。

### 2.3 点击与关闭选项

- 默认建议：**点击 Tab 后关闭浮窗**（初次使用不遮挡网页）。
- 关闭模式：点击一行 → 激活目标 Tab 及所属普通浏览器窗口 → 成功后关闭管理窗。
- 保持模式：点击一行 → 激活目标 Tab 及普通窗口 → 浮窗继续存在，但可能退到后面；下次快捷键聚焦原浮窗。
- 设置通过浏览器本地存储持久记忆。
- 切换失败时给出可理解的提示，不把失败当成功；不应在失败时自动关闭窗口。
- 点击手柄拖动时不得触发“点击切换”；拖动结束不应误点目标。

### 2.4 快捷键

- 采用 `chrome.commands` 注册“打开或聚焦页序”操作，浏览器扩展快捷键页面可自定义。
- 实施前实测默认快捷键是否与 Edge 和其他已安装扩展冲突，不强制固化未经验证的组合。
- 绑定目标浏览器窗口必须发生在创建/聚焦管理浮窗之前；不能把浮窗当作被管理的“当前窗口”。
- 已存在的浮窗再次唤起时不复制实例；目标正常窗口已关闭时清晰提示，并安全绑定当前可用正常窗口。

## 3. Tab 管理范围和实时同步

### 3.1 数据模型

每个 Tab 至少使用：`tab.id`（唯一标识）、`windowId`、`index`、`active`、`title`、`url`、`favIconUrl`、`pinned`、`groupId` 等可获取字段。

- **绝不以标题/URL 当作唯一 ID**：不同 Tab 可以有完全相同的标题和网址。
- 只管理唤出时的一个 `type: normal` 主窗口；多浏览器窗口暂不合并列表，也不跨窗口移动。
- 区分普通与无痕上下文，本版默认普通窗口，不额外请求无痕访问。
- 插件浮窗是 `type: popup`，必须排除自身；从弹窗请求“当前窗口”时需使用既存目标 `windowId`，而不是无条件使用 API 的 current window。

### 3.2 双向同步规则

| 事件 | 预期动作 |
|---|---|
| 首次唤出 | 按浏览器 index 升序读取目标窗口 Tab |
| 浏览器新增/关闭 Tab | 列表即时增删，保持浏览器实际顺序 |
| 浏览器顶部拖动 Tab | 浮窗同步行顺序 |
| 浮窗中手动拖动 | 调用 Tab 移动 API 真正修改浏览器顺序，再刷新真实 index |
| 执行自动排序 | 真实移动 Tab，再读回浏览器顺序作为最终结果 |
| Tab 切换或标题/URL 变化 | 高亮与显示内容同步更新 |

- 监听 `tabs.onCreated`、`onRemoved`、`onMoved`、`onActivated`、`onUpdated`，并按需补充标签组、窗口相关事件。
- **浏览器真实 index 是最终权威数据**；不能仅重排浮窗本地数组后就提示成功。
- 处理 API 的异步事件、重入及并发：移动/排序中可暂时禁用重复提交，结束后重新查询实际顺序。
- 被移动 Tab 意外关闭、移动 API 拒绝、目标窗口关闭时须提示并重新同步，避免界面永久错乱。

## 4. 手动拖动排序

- 按住行左侧手柄向上/向下拖动；拖动时显示明确的插入位置指示。
- 合法落点释放后立即提交真实移动，不另设“保存排序”。
- `Esc` 取消、放回原位置、落点非法时不发生真实移动。
- 固定 Tab 与普通 Tab 不允许跨区拖动，不得隐式固定或取消固定。
- 标签组（Tab Group）须采用保守原则：不破坏已有组归属。v0.1.1 **先允许同一安全区段内排序**；跨组/组与非组之间移动若会导致拆组则禁用并提示。
- 搜索过滤期间禁用拖动；滚动或普通点击不会被误判为拖动。

## 5. 一次性自动排序

### 5.1 规则与入口

提供：**手动、按标题 A→Z / Z→A、按网站域名 A→Z / Z→A、按完整网址 A→Z / Z→A**。

- 选择下拉项只是指定规则；只有点击“执行排序”才真正移动 Tab。
- **不做持续自动排序**。排序后允许用户手动拖动，新增或更名 Tab 不再自动插入新序位。
- 当前已符合规则时提示“无需调整”；操作失败时反馈失败，界面重新依据真实顺序显示。

### 5.2 比较规则与边界

- 标题：使用稳定、可复现的文本比较（建议 `Intl.Collator`，考虑数字自然排序），中文/英文/数字混排均要测试；空标题使用统一回退值。
- 域名：使用 URL 解析后的 hostname，比较键可去除前缀 `www.`，把同站点聚拢；同域名时按标题稳定排序。
- 完整网址：比较规范化 URL 文本，同站点不同路径仍视为不同排序键。
- 相同排序键：依照原浏览器 index 稳定保序，重复排序不反复跳动。
- 非普通 URL（`edge://`、`chrome://`、`about:`、扩展页、无 URL）：作为特殊项安全处理，不影响其他网页正常排序；明确固定放在普通网址项之后，特殊项相对次序稳定。
- 固定 Tab 默认保持其固定区域和原始相对顺序，不纳入自动排序。
- 已有标签组不拆组、不合组、不改归属；仅对可以保持组结构的区段排序。遇到无法安全排序的区段，应跳过并有可理解提示，不能为了排序而损坏分组。
- 无论何种规则，**不得跨普通浏览器窗口移动 Tab**。

## 6. 窗口尺寸、记忆和一键自动适配

### 6.1 唯一尺寸机制（已确认）

> **不设固定/智能/持续自动多个模式。只有：平时保持记忆尺寸 + 自由手动缩放 + 用户点击按钮后一次性自动适配。**

| 场景 | 窗口行为 |
|---|---|
| 初次打开 | 使用合理默认尺寸，建议先以约 500×600 CSS 像素实测 |
| 用户拖动 | 更新位置记忆 |
| 用户手动缩放 | 更新尺寸记忆 |
| Tab 数量变化或标题变更 | **不改变窗口尺寸** |
| 用户点击“自动适配” | 依据当前全部 Tab 标题和数量计算宽度、换行后的高度 |
| 关闭再开启 | 恢复最后一次手动或自动适配结果 |
| Edge 重启 | 继续恢复持久化设置 |

### 6.2 “自动适配窗口大小”按钮算法

1. 以目标窗口**全部 Tab** 为测量依据（即使当前存在搜索过滤，也不按搜索子集缩小窗口）。
2. 根据实际字体、字号、行内容、图标、手柄、工具栏、内边距计算内容宽度；不把字符数直接当像素数。
3. 优先增加宽度以尽量显示完整标题；建议最小宽度约 360 CSS px，最大宽度不超过所在屏幕**工作区**的 80%。
4. 达到宽度上限时，长标题换行（或通过完整标题提示访问）；测量换行后的实际行高。
5. 依据 Tab 数量和每行高度、搜索栏、工具栏、边距计算高度；高度不超过所在屏幕工作区约 85%。
6. 超过最大高度时列表内部滚动，不能无限撑大窗口；须保证可操作的最小高度。
7. 优先保留现有窗口左上角坐标；若缩放后超出屏幕边界，将窗口移动回可见区域。
8. 适配后保存真实窗口边界；连续点击按钮结果稳定，不产生累积误差。
9. 实测 Windows 100%/125%/150% DPI 缩放下的 CSS 尺寸、窗口外框尺寸、屏幕实际可用尺寸差异。

### 6.3 多屏与恢复

- 记录 `left / top / width / height`，如有必要记录显示器标识或依据工作区重新识别。
- 允许副屏、负坐标屏幕布局及不同分辨率；同样布局时重新打开优先回到上次显示器。
- 副屏拔掉、主副屏切换、分辨率改变时避免窗口完全位于可见屏幕之外；需提供回退到主屏可见区域的逻辑。
- 对窗口大小和位置监听实行适当防抖；关闭或重新打开前可再次读取真实边界补齐记忆。
- 若浏览器版本不提供足够的显示器工作区信息，可评估 `chrome.system.display` 权限；必须先验证兼容性和权限必要性。

## 7. 技术方案与权限建议

### 7.1 架构

- **Manifest V3**。
- 后台 Service Worker：命令入口、浮窗单例、绑定目标正常浏览器窗口、监听窗口/Tab 事件、协调数据同步。
- Extension 管理页面：竖排列表、搜索、拖动排序、自动排序选项、自动适配算法及 UI 提示。
- 本地存储 `chrome.storage.local`：点击后保持开关、窗体边界与少量偏好设置。
- 技术优先 TypeScript + HTML/CSS；是否用轻量前端框架以开发成本评估为准，避免不必要的复杂依赖。
- 不依赖后端服务，也不注入 content script 阅读网页正文。

### 7.2 预计使用的浏览器接口

- `chrome.windows.create / get / getAll / getLastFocused / update / remove / onBoundsChanged / onRemoved`。
- `chrome.tabs.query / update / move` 及标签创建、更新、移动、关闭、激活事件。
- `chrome.commands.onCommand` 与 Manifest 命令声明。
- `chrome.storage.local`。
- `chrome.tabGroups`（如为保护标签组需要获取分组元信息）；`chrome.system.display`（仅确证双屏工作区需求必需时）。

### 7.3 权限与数据安全

- 只申请必要权限，预计至少 `tabs`、`storage`；其他权限依真实方案申请。
- 只读取 Tab 标题、网址、favicon 和排列/分组状态，不读网页 DOM、Cookie、密码、输入框内容。
- 不上传任何 Tab 信息到远端；本地独立运行。
- 无 URL、受限内部页面、图标不可用或权限不足时展示合理回退，不得报错中断整个列表。
- 不要因为使用排序而额外索取全站 host 权限。

### 7.4 建议目录规划（仅建议，不在本次创建代码）

```text
Yexu/
├─ manifest.json
├─ src/
│  ├─ background/    # 窗口生命周期、命令与事件
│  ├─ ui/            # 独立管理窗口界面
│  ├─ core/          # Tab 模型、排序、保护边界
│  └─ storage/       # 偏好、浮窗几何信息
├─ tests/            # 排序算法与交互测试
└─ docs/             # 需求文档与后续验证记录
```

## 8. 实施顺序（后续开发阶段）

- **阶段 A**：扩展最小骨架、独立管理窗、快捷键、单例唤出。
- **阶段 B**：绑定普通主窗口、读取列表、显示完整标题、搜索、点击切换与保持/关闭。
- **阶段 C**：事件双向同步、真实手动拖动排序、错误处理。
- **阶段 D**：三种维度的一次性自动排序；重复键、固定标签和分组保护。
- **阶段 E**：持久记忆窗体位置尺寸、双屏恢复、按钮按需自动适配。
- **阶段 F**：Edge 实机验收、使用说明、解压安装说明、打包发布。

上述为实施任务顺序，**并非缩减 v0.1.1 核心交付目标**。

## 9. 验收清单

### 9.1 展示/切换

- [ ] Edge 同时打开 30 个以上 Tab，浮窗可列出目标窗口全部 Tab，标题可完整查看。
- [ ] 列表顺序与浏览器左→右严格相同，浏览器端变更立刻同步。
- [ ] 重复标题、重复网址仍可以正确激活指定 Tab。
- [ ] 当前激活项高亮正确；搜索标题/网址过滤正常，清除过滤还原顺序。
- [ ] 保持/关闭两种行为按设置生效、重启保留，保持不误称为置顶。
- [ ] 快捷键和扩展图标入口可唤出，重复执行不生成两个浮窗。

### 9.2 排序

- [ ] 浮窗手动拖动使浏览器顶部 Tab 真实改变顺序。
- [ ] 直接拖动浏览器 Tab 后，浮窗实时跟随且不反向覆盖。
- [ ] 标题、域名、完整网址分别支持升序与降序的一次性排序。
- [ ] 中文/英文/数字、同域名不同路径、空标题/URL、特殊浏览器页、相同排序键结果稳定。
- [ ] 修改 Tab 标题或新增 Tab 不触发隐式自动排序。
- [ ] 固定 Tab 不被解除固定；已有标签组不被误拆分、合并或转组。
- [ ] 搜索过滤期间禁止拖动/自动重排；API 失败或关闭 Tab 期间无永久错乱。

### 9.3 浮窗与环境

- [ ] 浮窗可自由拖动与手动缩放；关闭/打开及 Edge 重启后位置尺寸保持。
- [ ] 一键“自动适配”根据全部 Tab 标题真实测量宽度、高度；超屏后内部滚动。
- [ ] Tab 数量、标题变化不会自动触发窗口尺寸变化。
- [ ] 自动适配后的大小、手动缩放后的大小均按最后一次操作持久化。
